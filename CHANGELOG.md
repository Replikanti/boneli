## [Unreleased]

### Added

- Architecture proposal (`docs/ARCHITECTURE.md`) and ADR process.
- Cargo workspace with the core crates `boneli-domain` and `boneli-app`.
- CI: issue-link gate, rustfmt, clippy, tests, architecture rules and
  `cargo deny`.
- ADR-001: semantic core purity, `unsafe` containment and a transitive
  dependency allowlist.
- `tools/architecture.toml`: roles, checked platforms and an allowlist of
  dependency edges, each with a reason and the decision that approved it;
  `libc` is strict, so every edge into it needs its own accepted ADR.
- Fail fixtures for every architecture rule (`tools/fixtures/arch/`), run in
  CI by `tools/check-architecture.sh --fixtures`.
- `boneli-domain`: the run state machine (`Run::handle`), its events,
  commands and outcomes, the reproduction, citation, root-cause and fix
  gates, and budget accounting in micro-USD and milliseconds (ADR-002).
  Blank caller input is a `DomainError`: ticket key or title, forge
  references, `JobFailed` details and evidence references.
- `boneli_domain::scenarios`: 63 event sequences that the domain's unit
  tests and the replay gate fold (70 with the patch check, ADR-023).
- `boneli-replay-check`: a test-only root that folds the scenarios in two
  child processes and in its own, checks that address randomization is on,
  and compares the `Debug` output and the `Display` of every error byte for
  byte; the gate for address leaks
  from the domain (ADR-001, ADR-002).
- ADR-002: run state machine, budget units, gates and the replay gate.
- `boneli-http` (ADR-003): a strict HTTP/1.1 subset on `httparse`, with a
  Unix-socket server (one thread per connection, connection cap, idle,
  request and write timeouts), a client over any stream, Content-Length,
  chunked and close-delimited bodies, CONNECT on both sides, and
  unbuffered pass-through for server-sent events. Hosts are a canonical
  IPv4 address, a bracketed IPv6 address or an LDH name whose last label
  is not a number; `Host` is validated and must name a CONNECT's target
  (its port may be left out). The client sends no request on a stream
  where input has already arrived, the first request included, and reuses
  a connection only while the peer stays quiet (`IdleCheck`). ADR-003
  approves httparse's build script.
- `boneli-app`: the ports `Agent`, `Verifier`, `Forge`, `EventStore`,
  `Evidence`, `Clock` and `Ids` as synchronous, object-safe traits;
  `JobFailure`, whose detail is never blank; `ForgeRef`, never blank; and
  `replay` of a stored run log (ADR-004).
- `boneli-app`: the `DebugTicket` use case, which drives a run through the
  ports one command at a time, appends only accepted events, and hands a
  re-run after triage questions the previous run's questions (ADR-004).
- `boneli_app::contract`: contract suites for the seven ports, 23 clauses,
  which return the violated clause instead of panicking and which real
  adapters reuse. Evidence references must be derived from content and
  checked on read (`EvidenceError::Corrupted`), so the pull request carries
  the bytes the verifier checked.
- `boneli-memory`: the in-memory adapters of the seven ports, with their
  contract tests. `MemoryEvidence` names blobs by an FNV-1a digest.
- `boneli-replay-check`: an app corpus of 1 786 `DebugTicket` scenarios,
  1 755 of them generated by injecting every fault kind at every port call
  of every hand-written scenario, and the contract mutant table (29 mutant
  cases, one per clause and per checked operation), whose violations are
  rendered too. All are played in the two-process replay gate, which now
  also covers `boneli-app`.
- ADR-004: ports, in-memory adapters, contract suites and `DebugTicket`;
  `Verifier` is a port, implemented on `Sandbox` and `Git` in #17.
- `boneli-app`: the ports `Sandbox`, `Git`, `ImageStore` and
  `DataSnapshot`, minimal until their real adapters extend them, and
  `RelativePath`, which ports take for paths and which follows the citation
  path rule through `boneli_domain::gate::path_problem` (ADR-004, D11).
- `boneli_app::contract`: suites for the four infra ports, 25 more clauses
  (48 in total), each with a mutant in `boneli-replay-check` (54 mutant
  cases); `copies-independent` is the data adapter's acceptance as a
  clause.
- `boneli-memory`: `MemorySandbox`, `MemoryGit` with its own snapshot and
  diff formats, `MemoryImageStore` and `MemoryDataSnapshot`.
- `boneli-https` (ADR-005): a TLS client on rustls with the ring provider,
  TLS 1.3 and 1.2, ALPN `http/1.1`, Mozilla's roots from `webpki-roots`
  plus roots the caller adds, the handshake inside `connect` and
  `connect_over` (for CONNECT tunnels), no way to turn verification off,
  no 0-RTT and no key log. A close without `close_notify` is an error.
  `ConnectOptions` has a total handshake deadline next to the connect and
  I/O timeouts, for `connect` and `connect_over` alike. Its idle check
  counts plaintext and records rustls holds and follows the record framing
  of every byte read, so a response that arrives inside TLS while a
  connection is idle ends it, even when only part of its record has
  arrived, and complete session tickets do not.
- `boneli-http`: `Tunnel` is a `Transport` when its stream is one.
- ADR-005: the TLS exception to pure Rust: the 15 crates of the stack and
  their edges, the edges `getrandom -> libc` and `ring -> libc`, ring's C
  and assembly build, the approved build scripts of external crates, and
  the license exceptions.
- `tools/architecture.toml`: records for the TLS stack, and
  `build-script = "ADR-NNN"` on every external crate with a build script
  (`httparse`, `libc`, `ring`, `rustls`).
- The architecture rule `dep-build-script`: every reachable external crate
  with a build script needs an accepted ADR that says `<crate>'s build
  script is approved`; with fixtures for renamed scripts, `build = false`,
  build-dependencies, Windows-only dependencies, malformed keys, an ADR
  about another crate, a rejected ADR, and names hidden in comments or
  glued to longer names.
- `deny.toml`: per-crate license exceptions for ring, untrusted and
  rustls-webpki (ISC), subtle (BSD-3-Clause) and webpki-roots
  (CDLA-Permissive-2.0).
- `boneli-egress` (ADR-006), the pure policy of the egress proxy: an
  allowlist of exact canonical `host:port` names, parsed with the CONNECT
  target grammar (empty lists, IP literals and duplicates are refused);
  address classes that allow only globally reachable addresses, checked
  against the IANA special-purpose registries, and that also check the
  IPv4 address embedded in a NAT64 prefix (RFC 6052 lengths, prefixes from
  RFC 7050 discovery or the runner; a prefix only adds refusals); the
  connect order (families
  alternate, RFC 8305) and the per-attempt share of the connect budget; and
  the connection log codec, one record per line in a closed alphabet with a
  strict parser that accepts exactly one spelling of every record.
- `boneli_http::Target::parse_authority`: the CONNECT target grammar for
  values outside a request head.
- ADR-006: the egress proxy, its allowlist, address policy, connect budget,
  answers, relay, write-ahead connection log and server limits.
- The `boneli-egress` binary (ADR-006, part 2 of #10): `--socket <path>
  --allow <host:port> ... [--nat64-prefix <ipv6>/<len> ...]`; binds without
  replacing what is at the path, discovers the NAT64 prefixes through
  `ipv4only.arpa`, writes the `start` record and serves CONNECT. A name off
  the list is refused (403) and never resolved; an allowed name is
  resolved once and refused (403) if any address is not global; connects
  follow the family order within a 10 s per attempt and 30 s total budget
  (502, 504); other methods get 405 with `Allow: CONNECT`. Open tunnels
  relay bytes in both directions with half-close, a shared 660 s idle
  timeout and byte counts. Every connection gets exactly one terminal log
  record on stdout, each decision is logged before its effect, and a log
  that cannot be written stops the connection and exits with 3. Exit codes
  2 (usage), 1 (bind, discovery, accept), 3 (log); a panic aborts. The
  `Upstream` and `LogSink` seams, `MonotonicClock` for the `Clock` port,
  and `launch` with the startup order. ADR-006 now records measured peak
  connections of npm and pip installs, the getaddrinfo wait on dead name
  servers and the silences of a streamed API response.
- `boneli_http::accept_loop`: the accept loop and connection cap of
  `serve`, with each accepted stream handed to a callback, so a caller can
  log what `serve_connection` returns; `serve` is now built on it.
- `boneli-sys` (ADR-007, part 1 of #6): the sandbox runtime's first
  layer on `libc`. `spawn` starts a program in a new user namespace
  through a raw `clone3` with a pidfd; the child maps one id inside to the
  caller's uid and gid (`Ids`, single id mapping, `setgroups` denied),
  starts a new session, resets every signal disposition and the signal
  mask (every signal stays blocked from the clone until then, so no
  handler of the caller runs in the child), keeps only the three stdio
  descriptors and the given environment, and execs, without allocating. A failed step comes back as
  `Error::Setup` with the step, item and errno over a close-on-exec pipe;
  a setup timeout or a malformed report kills and reaps the child. The
  pipe's write end sits at descriptor 3 or above, so it survives a caller
  with 0-2 closed. Callers
  running as root or setuid are refused. `Features::probe` tries every
  host feature the runtime needs (user namespaces with the map writes,
  `clone3`, `close_range`, `SECCOMP_RET_KILL_PROCESS`, an installed
  allow-all seccomp filter, Landlock ABI 2,
  cgroup v2 and delegation of the caller's cgroup) and names each missing
  one with a stable id and its cause, AppArmor's user-namespace
  restriction included.
- ADR-007 (proposed): the single id mapping, the seccomp policy table,
  the kernel floor (Linux 5.19), the spawn model, the host tests and CI,
  and the lints of the unsafe crate.
- `boneli-sys` (ADR-007 D7, part 2 of #6): `spawn` takes a required
  `Root` and starts the program in new user, mount, PID, network, IPC,
  UTS and cgroup namespaces (the cgroup namespace created by the child).
  The root is a read-only bind of one layer or a read-only overlay of
  several (`userxattr`, options within one page), on a staging directory,
  followed by `Mount::Bind` (same kind as the target, flags only added),
  `Tmpfs`, `Overlay`, `Proc` and `Dev` (a read-only 64 KiB tmpfs with six
  host device nodes, a private `devpts`, `shm` and the standard
  symlinks), `pivot_root` with the old root detached, the hostname and
  `lo` up. Mount targets are resolved beneath the new root without
  following any symlink; every host path the child mounts — bind sources,
  the staging directory, the overlay root's layers and `Mount::Overlay`'s
  `lower`, `upper` and `work` — is opened without following any symlink,
  so a symlinked layer or overlay directory fails closed (ELOOP). The
  overlay mounts name the opened descriptors (`/proc/self/fd/<n>`) and
  hold them across the mount, so a host thread swapping a path for a
  symlink cannot redirect a layer or directory; the root overlay is
  capped at 163 layers by the one-page option limit. `InsidePath`,
  `Hostname` and the mount rules (no hidden or duplicate targets, no size
  0) are checked before the clone. Every host test runs on a fixture
  root.
- `boneli-sys` (ADR-007 D8, part 3 of #6): cgroups v2. `Parent::open`
  takes a delegated cgroup with cpu, io, memory and pids enabled for its
  children, and `Parent::vacate_and_delegate` makes one out of a delegated
  scope or service. `Cgroup::create` writes `memory.max`,
  `memory.swap.max`, `pids.max`, `cpu.max`, `io.max` and
  `memory.oom.group = 1` and reads each back before any process enters;
  `Limits` has no default and checks the kernel's bounds; `destroy` kills
  with `cgroup.kill`, waits for an empty cgroup and removes it. `Spec`
  takes a required `cgroup`, and `clone3` places the child there with
  `CLONE_INTO_CGROUP`, before the child creates its cgroup namespace.
  Every directory and file is reached through descriptors opened once.
  `Mount::Cgroup2` shows the sandbox's own cgroup read-only.
  `block_device_of` finds the disk behind a path for `io.max` and refuses
  a multi-device btrfs. Every host test runs in a cgroup with small
  limits. Review fixes: `destroy` lifts `io.max` and `cpu.max` after the
  kill, so a task in throttled IO cannot outlast the kill bound; a failed
  drop is reported on stderr and in `leaked_cgroups()`; every cgroup has
  `cgroup.max.descendants` and `cgroup.max.depth` 0; `Features::probe`
  requires `nsdelegate` (`cgroup-nsdelegate`); the child raises a
  negative inherited `oom_score_adj` to 0 (`Step::OomScoreAdj`).
  Teardown tries every step and returns `Error::CgroupTeardown` with the
  path; a cgroup `destroy` could not remove is listed by
  `leaked_cgroups()` too; `Parent::open` and `vacate_and_delegate` refuse
  a hierarchy without `nsdelegate` themselves. Teardown lifts limits only
  after a successful kill, and kills through a `cgroup.kill` descriptor
  held open since `create`, so a mode change from inside cannot block it.
- `boneli-sys` (ADR-007 D2, D9 and D10, part 4 of #6): the seccomp
  policy, assembled in Rust (`seccomp::{table, bpf, policy}`, 69
  instructions): foreign architectures killed, numbers above 471 ENOSYS,
  `io_uring_*`, `bpf`, `userfaultfd`, `perf_event_open`, the keyring
  calls, `syslog`, new user namespaces through `clone` and `unshare`, and
  the huge page flags of `mmap`, `shmget` and `memfd_create` EPERM,
  `clone3` ENOSYS, socket families other than Unix, IPv4, IPv6 and netlink
  and `socketpair` other than Unix EAFNOSUPPORT, netlink protocols other
  than routing and IPv4/IPv6 protocols other than 0, TCP, UDP and the
  family's ICMP EPROTONOSUPPORT, `socket(AF_INET, SOCK_PACKET)`
  EAFNOSUPPORT (the kernel would make it a packet socket),
  `ioctl(TIOCSETD)` and the eight bridge and VLAN socket ioctls EPERM (no
  line discipline, bridge or 8021q module can be loaded). ADR-007 D2 lists
  every `request_module` call site of Linux 7.2 (326: 42 covered by rows,
  279 unreachable without a capability, 5 residual with a host-side
  mitigation: tc classifiers named in `RTM_GETTFILTER`, crypto algorithms
  by fixed name). `Features::probe` refuses a host without usable kernel
  keyrings (`keyrings`). The sandbox's procfs masks
  `/proc/keys` and `/proc/key-users` with `/dev/null`, and the child joins
  a new anonymous session keyring before its mounts, so the runner's keys
  are neither listed nor possessed. Every `spawn` drops every capability
  (locked securebits 0xEF, an empty bounding set up to `cap_last_cap`, no
  ambient, `capset` to zero), sets `no_new_privs` and installs the filter
  as the last step before `execve`; it refuses a source on hugetlbfs
  (`Error::HugetlbfsSource`). `Ruleset` applies Landlock (ABI 2 to 10) to
  the calling process and fails closed on a right the ABI does not know.
  Tests: a BPF interpreter over both architectures' programs, the rows in
  the kernel against an unfiltered baseline (`BONELI_SYS_HOST_GAPS` now
  takes `syslog`, `shmget-hugetlb`, `socket-inet-packet`, `ioctl-siocgifbr`
  and `hugetlbfs-mount`), the privilege
  drop seen from inside, Landlock rights on the host, the cgroup2 view
  that no mount call can make writable; two PR 3 tests make their
  capability step on the host side now.
- `boneli-sys` (ADR-007 D2, part 5 of #6, ADR-007 accepted): the census
  of every syscall of the Linux 7.2 tables (385 names: 267 `Own`, 83
  `NeedsCap`, 21 `Row`, 14 `NotImplemented`), tied to the extracts and the

  `FS_IOC_SET_ENCRYPTION_POLICY` and `FS_IOC_ENABLE_VERITY` answer EPERM.
  ADR-007 D2 lists every by-name crypto allocation of 7.2 (305: 46

  `setsockopt-tcp-md5`, `nosys-<name>` and `alarm-rtc`; the kTLS kernel
  row follows the host's `tcp_available_ulp`.

- `boneli-json` (ADR-008): a strict RFC 8259 parser and a compact,
  deterministic serializer without derive or dependencies. `Value` keeps
  object members in input order and numbers as their lexemes; duplicate
  keys, lone surrogate escapes and a leading BOM are rejected. `Limits`
  has no defaults and bounds input bytes, nesting depth (at most
  `MAX_DEPTH`, 512) and the number of values. `ndjson::Reader` and
  `write_line` read and write one value per line with bounded lines.
  Parsed containers and strings hold no spare capacity, and `Debug` of a
  value is compact and linear in its output, with or without `#`.
  Tested against JSONTestSuite, vendored with its MIT notice, a
  305,491-mutant sweep, round trips and a stack gate on a 1 MiB thread.
- ADR-008: the JSON subset, the number model, duplicate-key rejection,
  the limits with their memory measurements, and the depth ceiling with
  its stack measurements.
- `boneli_https::Sha256`: ring's SHA-256 through rustls' public hash

- `boneli-sys` layer primitives for the overlay format: `make_whiteout`

- `boneli-oci`, part 1 of #7 (ADR-009, proposed): unpacks a plain, gzip or
  zstd layer into its own directory in the overlay format, with our own
  tar reader (Go's subset) and gzip framing over `miniz_oxide`, zstd
  through `ruzstd` 0.9.1 with a 100 MiB window cap.
  Paths with `..`, writes through symlinks, root-level opaque markers and
  invalid whiteouts refuse the layer; setuid and setgid bits, ownership
  and tar xattrs are dropped; devices other than 0:0 whiteouts are
  skipped and counted. `Limits` (no defaults) cap layer and image bytes,
  image entries and extension headers while the stream is read.
  Directories created for missing parents count as entries, and paths
  deeper than the depth limit are refused. `LayerCache` commits a layer
  by rename only when its bytes hash to its `diff_id`, after one `syncfs`
  (`boneli_sys::sync_filesystem`) and with the sidecar and the rename
  synced, charges the budget only on commit, and removes a failed tree
  with one directory descriptor at a time, listing each directory once.
  Trees are staged as dot names inside `layers/sha256/`, so the commit is
  a rename within one directory. The store refuses a case-insensitive or
  normalizing layer directory, and the unpacker refuses a directory it
  did not create (a case or normalization alias).
- ADR-009 (proposed): the layered format, path, type and metadata rules,
  the tar subset, the decompressors, SHA-256 from ring, the limits and
  the cache layout.
- `boneli-oci`, part 2 of #7: the registry client. `Reference` parses an
  image's registry host, repository path, `sha256` digest and platform
  strictly, before any request. `Client` fetches indexes, manifests,
  configs and blobs from an allowlisted `Registry` over `boneli-http` and
  `boneli-https` (`Registry::docker_hub()` has the measured hosts), with
  the anonymous Bearer token flow (one re-authentication per fetch), and
  resolves an image to its platform's manifest and config. Every document
  and blob is checked against its digest; a blob must be exactly its
  descriptor's size and is renamed into place only then. Redirects (blobs
  only, at most 10) go to the API host or a host under a redirect suffix,
  `Authorization` only to the API host. `FetchLimits` and `Timeouts` (no
  defaults) bound documents, token responses, response heads, layer
  counts, blob sizes, the total download of one pull (config and layer
  descriptor sizes, summed when the manifest is read) and every fetch's
  deadline, which `TlsDial` also holds below TLS. `TlsDial` refuses a host
  outside ADR-003's grammar before it resolves or connects. Failures are
  `PullError::NotFound` or `Failed` with a detail; a `404` is `NotFound`
  only for the manifest the reference names, `Failed` for one an index
  names (ADR-009, D11).

- `boneli-oci`, part 3 of #7: `OciImageStore`, the `ImageStore` adapter.
  `open` takes an absolute, private root owned by the caller (refusing
  `,`, `:`, `\` and non-UTF-8 names before and after it is resolved),
  removes temporary names whose owner is gone, and fails at once on a
  filesystem without 0:0 whiteouts or `user.*` xattrs. `pull` keeps
  indexes, manifests and configs under `blobs/sha256/`, re-hashed on every
  read, fetches only missing blobs, unpacks only missing layers, removes a
  layer blob once its layer is committed, and returns
  `sha256:<platform manifest>`, stable across restarts. `layers` lists a
  pulled image's layer directories bottom first (a repeated `diff_id`
  keeps its topmost place), `config` its runtime fields (`User`, `Env`,
  `Entrypoint`, `Cmd`, `WorkingDir`). `StoreConfig` carries the values of
  ADR-009 D7 and D12 (`StoreConfig::mozilla()` for production).

- The `Git` contract gains `workspace-metadata-inert`, part 1 of #30
  (ADR-010, proposed): repository metadata planted in a workspace (`.git`,
  also nested) runs nothing, leaves the diff unchanged, does not change
  later diffs or applies of the same or a fresh checkout, and a diff that
  writes it does not apply. `RelativePath::is_repository_metadata` is the
  one rule (some component is exactly `.git`); `MemoryGit` drops metadata
  from a workspace and refuses a diff that touches it. The suite takes a
  `retarget` hook and a `Tripwire` fixture; one mutant per sub-check
  (`RunsMetadata`, `MetadataIsContent`, `AdoptsPerCheckout`,
  `AdoptsIntoNewCheckouts`, `AdoptsOnApply`, `AppliesMetadata`): 50
  clauses, 62 mutant cases. Fixture guards require every metadata entry
  to reach the workspace and every diff pointed at metadata to apply
  once moved back to content. `boneli_replay_check::mutants` gains a
  regression table (5 mutants) and vacuous-fixture violations (5), both
  rendered under the replay gate.
- `boneli-git-cli`, part 2 of #30 (ADR-010 D2 and D3, still proposed):
  the workspace format and the materializer; no git runs yet.
  `Workspace` encodes a tree canonically (a magic line, then files,
  executables and symlinks in path order, length-prefixed), and
  `Workspace::decode` refuses a wrong magic, an unknown kind, a length
  past the end, a path the citation path rule refuses, unsorted or
  duplicate paths, an entry beneath a file or symlink entry (every
  ancestor, in linear time), an empty or NUL-holding link target and
  more nodes than the cap: files, symlinks and every directory they
  imply, 200,000 by default (`Workspace::nodes`).
  `Workspace::from_sorted` builds a workspace from entries in path
  order (as `git ls-tree -r -z` lists them) under the same checks and
  cap, also in linear time, and refuses unsorted or duplicate input.
  `without_metadata` drops repository metadata. `materialize` writes a workspace into a
  new, empty 0700 directory with `create_new` and explicit modes (also
  under any umask), creates each directory once, never writes through an

- `destroy_lifts_io_throttle` writes with the probe instead of `dd` and
  checks before the kill that `io.max` holds the writer inside its one
  40 MiB write (`/proc/<pid>/task/<tid>/syscall` and `wchar`, with the
  task state as a named fallback where the runner refuses those files)
  and that the `io.max` device counted a write, waiting up to 10 s after
  the spawn for the first count, so a host where the limit does not hold
  fails with a message that says so. The probe's write buffer is advised
  `MADV_NOHUGEPAGE`, so the size of the first bio, and with it the time
  of the first count, does not depend on the host's THP setting. On AWS-hosted CI
  runners the image's `dd` had fallen back to a buffered write. ADR-007
  records the cause, that buffered writers under `io.max` are OOM-killed

  file-lock type of the workspace, `boneli_private_dir::lock`: `FileLock`
  for a lock its process keeps, `HandOff` for locks taken to be handed to
  another process, one release with the one owner check (pid and pid
  namespace) for both, and the bounded wait. `boneli-store-fs` and

- Architecture rule `file-lock` (part 2 of #109, ADR-030 accepted): a

  not scanned. ADR-026 and ADR-028 are superseded by ADR-030.
- `Sandbox` port (part 2 of #8, ADR-042 D2, still proposed): a sandbox is
  a pod. `SandboxSpec` holds containers (`ContainerName`, an RFC 1123
  label that is not `localhost`), the workspace copied in at `create`
  (`WorkspaceBytes`, whose `Debug` prints only the length), dependency
  layers, brokers (`BrokerName`) and `PodLimits`; memory and the process
  count move from the per-command `Limits` to the pod, which keeps
  `wall_ms` and gains `output_bytes`. `Command` names its container,
  `ExitStatus::TimedOut` is the wall limit, and `start`, `export`,
  `seal` and `release` are new. `SandboxSpec::check` and
  `PodLimits::check` hold the pod relations both adapters use (storage
  sum within `memory_bytes`, `n + 2` tasks, `cpu_millis` at least 10, no
  zero size, no broker in a verify sandbox); only a prepare sandbox can
  be sealed. The contract suite grows from 7 to 24 clauses, with three
  stronger ones and one mutant per new clause (79 clauses, 96 mutant
  cases): read-only layers that outlive and do not follow the sandbox
  they were sealed from, seals and copy-outs that follow no symlink (a
  relative one included), the output cap on both streams, overlapping
  dependencies refused, a running service, exports without the mounts
  and commands that run in the container they name. `MemorySandbox`
  keeps files and symlinks, files outside the workspace and sealed
  layers, and checks the spec, the layers and the output cap.

### Fixed

- `boneli-sys` host tests (#142): `keeper_reads_its_own_sandbox` no
  longer fails on a loaded host. It checks wiring and liveness (each
  keeper reads its own `memory.stat` in at least 5 of 20 slots, the
  parent's in at most 5, the keeper keeps reading, no failure, no pause
  over 3 s); the keeper's cadence is pinned by unit tests that drive
  its loop on a fake clock through a private `Clock` seam, exactly
  (reads, late reads, longest gap, re-anchoring after a freeze), and the
  real wait by a unit test that the quickest of up to 200 one-period
  waits ends within 1.5 periods.
  `buffered_writes_without_io_max_are_not_killed` reruns an inconclusive
  `NotBuffered` run, up to 5 attempts; every other verdict decides at
  once.
- `boneli-oci` (#117, ADR-035, accepted): a Docker Hub blob request that
  Docker Hub redirects to its S3 host
  `docker-images-prod.s3.dualstack.us-east-1.amazonaws.com` is followed
  instead of failing the pull with "not on the allowlist". The host is
  admitted exactly, not by suffix, through the new
  `Registry::with_redirect_hosts`: another bucket, region, endpoint form
  or port is still refused, and the blob is still checked by digest.
- `FsStore` (#94, ADR-026) releases its lock by an explicit unlock when it
  drops, and on every error of `open` after the lock is taken: a reopen
  no longer fails with `InUse` while a process spawned by another thread
  is between fork and exec and holds a copy of the lock. Only the process
  that took the lock unlocks it, so a copy dropped in a forked child
  leaves the parent's lock held.
- `FsStore` (#97, ADR-028) tells the lock's owner by its pid and its pid
  namespace: a copy dropped in a sandbox child, which is pid 1 of a new
  namespace, no longer unlocks the store of a runner that is pid 1 of its
  own.
- `boneli-oci` (#98) releases a lock it took on a lock file that was
  replaced before the inode check by an explicit unlock as well, before
  it tries again: a child spawned by another thread no longer keeps that
  stale lock held until its exec. The same holds for the pins
  `Lease::pin_descriptors` took before a later one failed. Pinned, with
  deterministic tests that a dropped shared, exclusive or removed cache
  lock and an abandoned pin descriptor are free at once while a child
  holds a copy of it, that `remove` unlinks before it unlocks, and that
  every lock file is `O_CLOEXEC`.
