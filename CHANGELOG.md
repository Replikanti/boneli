## [Unreleased]

### Added

- Architecture proposal (`docs/ARCHITECTURE.md`) and ADR process.
- Cargo workspace with the core crates `boneli-domain` and `boneli-app`.
- CI: issue-link gate, rustfmt, clippy, tests, architecture rules and
  `cargo deny`.
- ADR-001: semantic core purity, `unsafe` containment and a transitive
  dependency allowlist.
- `tools/architecture.toml`: roles, checked platforms and an allowlist of
  dependency edges, each with a reason and the decision that approved it;
  `libc` is strict, so every edge into it needs its own accepted ADR.
- Fail fixtures for every architecture rule (`tools/fixtures/arch/`), run in
  CI by `tools/check-architecture.sh --fixtures`.
- `boneli-domain`: the run state machine (`Run::handle`), its events,
  commands and outcomes, the reproduction, citation, root-cause and fix
  gates, and budget accounting in micro-USD and milliseconds (ADR-002).
  Blank caller input is a `DomainError`: ticket key or title, forge
  references, `JobFailed` details and evidence references.
- `boneli_domain::scenarios`: 63 event sequences that the domain's unit
  tests and the replay gate fold.
- `boneli-replay-check`: a test-only root that folds the scenarios in two
  child processes and in its own, checks that address randomization is on,
  and compares the `Debug` output and the `Display` of every error byte for
  byte; the gate for address leaks
  from the domain (ADR-001, ADR-002).
- ADR-002: run state machine, budget units, gates and the replay gate.
- `boneli-http` (ADR-003): a strict HTTP/1.1 subset on `httparse`, with a
  Unix-socket server (one thread per connection, connection cap, idle,
  request and write timeouts), a client over any stream, Content-Length,
  chunked and close-delimited bodies, CONNECT on both sides, and
  unbuffered pass-through for server-sent events. Hosts are a canonical
  IPv4 address, a bracketed IPv6 address or an LDH name whose last label
  is not a number; `Host` is validated and must name a CONNECT's target
  (its port may be left out). The client sends no request on a stream
  where input has already arrived, the first request included, and reuses
  a connection only while the peer stays quiet (`IdleCheck`). ADR-003
  approves httparse's build script.
- `boneli-app`: the ports `Agent`, `Verifier`, `Forge`, `EventStore`,
  `Evidence`, `Clock` and `Ids` as synchronous, object-safe traits;
  `JobFailure`, whose detail is never blank; `ForgeRef`, never blank; and
  `replay` of a stored run log (ADR-004).
- `boneli-app`: the `DebugTicket` use case, which drives a run through the
  ports one command at a time, appends only accepted events, and hands a
  re-run after triage questions the previous run's questions (ADR-004).
- `boneli_app::contract`: contract suites for the seven ports, 23 clauses,
  which return the violated clause instead of panicking and which real
  adapters reuse. Evidence references must be derived from content and
  checked on read (`EvidenceError::Corrupted`), so the pull request carries
  the bytes the verifier checked.
- `boneli-memory`: the in-memory adapters of the seven ports, with their
  contract tests. `MemoryEvidence` names blobs by an FNV-1a digest.
- `boneli-replay-check`: an app corpus of 1 786 `DebugTicket` scenarios,
  1 755 of them generated by injecting every fault kind at every port call
  of every hand-written scenario, and the contract mutant table (29 mutant
  cases, one per clause and per checked operation), whose violations are
  rendered too. All are played in the two-process replay gate, which now
  also covers `boneli-app`.
- ADR-004: ports, in-memory adapters, contract suites and `DebugTicket`;
  `Verifier` is a port, implemented on `Sandbox` and `Git` in #17.
- `boneli-app`: the ports `Sandbox`, `Git`, `ImageStore` and
  `DataSnapshot`, minimal until their real adapters extend them, and
  `RelativePath`, which ports take for paths and which follows the citation
  path rule through `boneli_domain::gate::path_problem` (ADR-004, D11).
- `boneli_app::contract`: suites for the four infra ports, 25 more clauses
  (48 in total), each with a mutant in `boneli-replay-check` (54 mutant
  cases); `copies-independent` is the data adapter's acceptance as a
  clause.
- `boneli-memory`: `MemorySandbox`, `MemoryGit` with its own snapshot and
  diff formats, `MemoryImageStore` and `MemoryDataSnapshot`.
- `boneli-https` (ADR-005): a TLS client on rustls with the ring provider,
  TLS 1.3 and 1.2, ALPN `http/1.1`, Mozilla's roots from `webpki-roots`
  plus roots the caller adds, the handshake inside `connect` and
  `connect_over` (for CONNECT tunnels), no way to turn verification off,
  no 0-RTT and no key log. A close without `close_notify` is an error.
  `ConnectOptions` has a total handshake deadline next to the connect and
  I/O timeouts, for `connect` and `connect_over` alike. Its idle check
  counts plaintext and records rustls holds and follows the record framing
  of every byte read, so a response that arrives inside TLS while a
  connection is idle ends it, even when only part of its record has
  arrived, and complete session tickets do not.
- `boneli-http`: `Tunnel` is a `Transport` when its stream is one.
- ADR-005: the TLS exception to pure Rust: the 15 crates of the stack and
  their edges, the edges `getrandom -> libc` and `ring -> libc`, ring's C
  and assembly build, the approved build scripts of external crates, and
  the license exceptions.
- `tools/architecture.toml`: records for the TLS stack, and
  `build-script = "ADR-NNN"` on every external crate with a build script
  (`httparse`, `libc`, `ring`, `rustls`).
- The architecture rule `dep-build-script`: every reachable external crate
  with a build script needs an accepted ADR that says `<crate>'s build
  script is approved`; with fixtures for renamed scripts, `build = false`,
  build-dependencies, Windows-only dependencies, malformed keys, an ADR
  about another crate, a rejected ADR, and names hidden in comments or
  glued to longer names.
- `deny.toml`: per-crate license exceptions for ring, untrusted and
  rustls-webpki (ISC), subtle (BSD-3-Clause) and webpki-roots
  (CDLA-Permissive-2.0).
- `boneli-egress` (ADR-006), the pure policy of the egress proxy: an
  allowlist of exact canonical `host:port` names, parsed with the CONNECT
  target grammar (empty lists, IP literals and duplicates are refused);
  address classes that allow only globally reachable addresses, checked
  against the IANA special-purpose registries, and that also check the
  IPv4 address embedded in a NAT64 prefix (RFC 6052 lengths, prefixes from
  RFC 7050 discovery or the runner; a prefix only adds refusals); the
  connect order (families
  alternate, RFC 8305) and the per-attempt share of the connect budget; and
  the connection log codec, one record per line in a closed alphabet with a
  strict parser that accepts exactly one spelling of every record.
- `boneli_http::Target::parse_authority`: the CONNECT target grammar for
  values outside a request head.
- ADR-006: the egress proxy, its allowlist, address policy, connect budget,
  answers, relay, write-ahead connection log and server limits.
- `boneli-sys` (ADR-007, part 1 of #6): the sandbox runtime's first
  layer on `libc`. `spawn` starts a program in a new user namespace
  through a raw `clone3` with a pidfd; the child maps one id inside to the
  caller's uid and gid (`Ids`, single id mapping, `setgroups` denied),
  starts a new session, resets every signal disposition and the signal
  mask (every signal stays blocked from the clone until then, so no
  handler of the caller runs in the child), keeps only the three stdio
  descriptors and the given environment, and execs, without allocating. A failed step comes back as
  `Error::Setup` with the step, item and errno over a close-on-exec pipe;
  a setup timeout or a malformed report kills and reaps the child. The
  pipe's write end sits at descriptor 3 or above, so it survives a caller
  with 0-2 closed. Callers
  running as root or setuid are refused. `Features::probe` tries every
  host feature the runtime needs (user namespaces with the map writes,
  `clone3`, `close_range`, `SECCOMP_RET_KILL_PROCESS`, an installed
  allow-all seccomp filter, Landlock ABI 2,
  cgroup v2 and delegation of the caller's cgroup) and names each missing
  one with a stable id and its cause, AppArmor's user-namespace
  restriction included.
- ADR-007 (proposed): the single id mapping, the seccomp policy table,
  the kernel floor (Linux 5.19), the spawn model, the host tests and CI,
  and the lints of the unsafe crate.
- `boneli-sys` (ADR-007 D7, part 2 of #6): `spawn` takes a required
  `Root` and starts the program in new user, mount, PID, network, IPC,
  UTS and cgroup namespaces (the cgroup namespace created by the child).
  The root is a read-only bind of one layer or a read-only overlay of
  several (`userxattr`, options within one page), on a staging directory,
  followed by `Mount::Bind` (same kind as the target, flags only added),
  `Tmpfs`, `Overlay`, `Proc` and `Dev` (a read-only 64 KiB tmpfs with six
  host device nodes, a private `devpts`, `shm` and the standard
  symlinks), `pivot_root` with the old root detached, the hostname and
  `lo` up. Mount targets are resolved beneath the new root without
  following any symlink, and host paths without following symlinks.
  `InsidePath`, `Hostname` and the mount rules (no hidden or duplicate
  targets, no size 0) are checked before the clone. Every host test runs
  on a fixture root.
- `Features::probe`: a seccomp probe child that cannot be started (a
  failed `clone3`, pipe or wait) is reported as `probe-failed` with the
  call and errno instead of as a missing seccomp filter.
- The architecture rule `sys-lints`: every crate in `roles.unsafe` keeps
  its own `[lints]` table with every workspace lint but `unsafe_code` at
  the same or a stricter level, the lints of the new
  `[check] unsafe-lints` array at forbid, and nothing else below
  deny; with fixtures.
- CI: the `sandbox` job on x86_64 and arm64 runners, which asserts what a
  stock runner lacks, prepares the host with the host-setup block from
  `CLAUDE.md` and runs the `boneli-sys` host tests; `check` also checks
  `boneli-sys` for `x86_64-unknown-linux-musl` and
  `aarch64-unknown-linux-musl`.
- `CLAUDE.md`: how to run the host tests, and the host-setup block (an
  AppArmor profile limited to the two `boneli-sys` test binaries, cgroup
  delegation of cpu, io, memory and pids, linger on headless hosts), the
  one source for users and CI.

### Changed

- `boneli_domain::gate::citation_problem` checks the path through the new
  `path_problem`, without a change in behavior (ADR-004, D1).
- The architecture check is now `tools/check_architecture.py` behind the
  same `tools/check-architecture.sh`. It reads the workspace from
  `cargo metadata`, checks every resolved dependency edge on both Linux
  targets, limits sources to crates.io and member paths, parses the manifest
  lint tables, scans every non-`boneli-sys` crate for `unsafe`, rejects
  `.cargo/config*`, `clippy.toml`, proc-macro crates, `#[path]` and
  `include!`, and fails on any tool error.
- `boneli-domain` and `boneli-app` are `#![no_std]` and build for
  `x86_64-unknown-none`; their doctests cannot use `unsafe`.
- The architecture check evaluates dependency `cfg`s itself against x86_64
  and aarch64 Linux with glibc and musl (core crates also on
  `x86_64-unknown-none`), treating flag-dependent conditions such as
  `crt-static` as true, instead of `--filter-platform`. It rejects crate
  roots that are not `.rs` files, build scripts outside
  `roles.build-script` (empty), and `rust-toolchain` files; CI pins
  `RUSTUP_TOOLCHAIN`. The core token scan matches `{:p}`-style specs (any
  fill character) in the raw content of every core file and in string
  literals after escape decoding (whitespace before the closing brace
  included), and also bans `Pointer`, `concat`, `stringify`, `env`,
  `option_env`, glob imports from `fmt`, `use` items built from macro
  metavariables, `core::task` paths and wakers, `{` or `}` in core file
  paths, and `include_str!`/`include_bytes!` paths that are absolute or
  contain `..` or a backslash.
